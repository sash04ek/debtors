# Указания для агентов — «Должники»

Настольная программа (Python + Tkinter, Windows и macOS): по отчёту ЕИРЦ о задолженности отбирает должников-физлиц и готовит документы (претензии, письмо в ЕИРЦ, заявления о судебном приказе). Подробнее о возможностях — в [README.md](README.md). Язык интерфейса, комментариев, коммитов, PR и описаний релизов — русский.

## Среда и команды

- Репозиторий `sash04ek/debtors`, основная ветка `main`. Локально: Python 3.14 + Tk 9, окружение `.venv` (`.venv/bin/python`). В CI: Python 3.12 + Tk 8.6 — код должен работать на обоих (например, события Tk 9 вроде `<TouchpadScroll>` на Tk 8.6 недопустимы без `try/except TclError`).
- Тесты: `.venv/bin/python -m unittest discover tests` (около 150, 2 пропущены — это опциональные e2e с `DEBTORS_NATIVE_E2E=1`). Запускать до каждого коммита. Статика: `.venv/bin/python -m pyflakes <файлы>`.
- Сборка macOS: `./build.sh` → `dist/Должники.app`. Windows и релизные артефакты собирает CI (PyInstaller, workflow «Сборка» на push и тег).
- Версия берётся из тега (`version.py` подставляется при сборке; в репозитории остаётся значение по умолчанию).

## Структура

| Файл | Назначение |
|---|---|
| `app.py` | главное окно, диалоги (`Dialog` — базовый класс), темы, меню |
| `widgets.py` | свои виджеты: `Card`/`section`, `Switch`, `PopupSelect`, `PopupMenu`, `Tabs`, `Badge`; `palette`, `retheme` |
| `datepicker.py`, `native_date.py` | выбор даты: системный (macOS — osascript/JXA, Windows — PowerShell) и запасной Tk |
| `core.py`, `claim.py`, `court.py`, `duty.py`, `numwords.py` | разбор отчёта, генерация docx, госпошлина (ст. 333.19 НК РФ) |
| `orgs.py`, `owners.py`, `courts.py`, `poa.py`, `precheck.py` | организации и дома, карточки собственников, судебные участки, чтение доверенностей, проверка перед созданием документов |
| `storage.py` | хранение в `~/.debtors/` (JSON, атомарная запись, `schema_version` и миграции, экспорт/импорт) |
| `tests/` | unittest; `tests/windows_shots.py` — снимки окон для CI на Windows |

## Данные и безопасность

- Данные программы живут в `~/.debtors/` (переменная `DEBTORS_HOME` переопределяет путь — в тестах используйте временную папку). Карточки собственников (`owners.json`, `trash.json`) — персональные данные, права 600, **только локально**.
- Не читать, не открывать и не копировать файлы и папки пользователя, на которые он не указал. Не выводить содержимое `~/.debtors` без необходимости.
- Токены и пароли, вставленные в чат, не использовать и не сохранять.
- **Никаких реальных данных в репозитории**: образцы организаций, примеры в комментариях, подсказках и тестах — вымышленные (организации «Ромашка», «Василёк», ФИО вроде «А. А. Иванов», нулевые ИНН/ОГРН/счета). Реальные названия, реквизиты, ФИО, адреса, телефоны, почты не добавлять. Публичные данные госорганов (названия и адреса судебных участков) допустимы.
- Тесты не должны зависеть от реальных данных пользователя: если код читает `~/.debtors`, изолируйте (`DEBTORS_HOME`, подмена `owners._load_all`, обнуление полей организаций в памяти).
- Формат данных менять только через `storage.SCHEMA_VERSION` и `MIGRATIONS`, с тестом миграции.

## Внешний вид — проверять глазами

Любое изменение интерфейса проверять по реальному снимку в светлой **и** тёмной теме, мелкие элементы — в увеличении, до слов «готово».

- **macOS:** снимать только своё окно: `screencapture -l <CGWindowID>` (id через `osascript -l JavaScript` и `CGWindowListCopyWindowInfo` по PID процесса и названию окна). Не снимать весь экран и окна пользователя. Мелкое — обрезать и увеличивать (PIL, LANCZOS).
- **Windows:** workflow «Снимки на Windows» (`.github/workflows/windows-shots.yml`) запускается на каждый PR, меняющий код, и вручную (`gh workflow run "Снимки на Windows" --ref <ветка>`). Скачать: `gh run download <id> -D <папка в scratchpad>`, посмотреть PNG, затем удалить. Он же автоматически проверяет яркость окон в тёмной и светлой теме. Не угадывать, как что-то выглядит на Windows, — снять.
- Новый диалог/окно добавлять в `tests/windows_shots.py`.
- Скачанные и снятые скриншоты — во временной папке (scratchpad), после просмотра удалять.

### Особенности платформ

- **Windows:** тема Sun Valley (`sv-ttk`); цвета из ttk-lookup пустые, поэтому палитра хранится явно в `root.theme_colors` (читают `widgets.base_colors`/`palette`). Тёмный заголовок окна — атрибут DWM (`set_titlebar_dark`). Системное меню не поддаётся тёмной теме, поэтому строка меню (`_build_tk_menubar`) и всплывающие меню (`widgets.PopupMenu` через `new_menu()`) рисуются самим Tk. DPI-awareness включается в `main()`.
- **macOS:** системные меню (`tk.Menu`), свои переключатели `_AquaSwitch` и списки `_AquaPopupSelect`; нативный календарь — не-ключевая панель, фокус остаётся в поле даты. Рисуя «таблетки» и кружки на `Canvas`, избегайте составных фигур из кругов и прямоугольников — на стыках видны ступеньки (капсула переключателя рисуется одной линией со скруглёнными концами).
- Все меню создавать через `new_menu(...)`, а не `tk.Menu` напрямую (кроме системных меню macOS).

## Код и тесты

- Стиль окружающего кода: плотные комментарии на русском, объясняющие «зачем», имена по-английски. Не плодить абстракции и не переписывать то, что не просили.
- Новая логика — с unittest рядом с похожими тестами. Платформенные ветки в тестах имитируются подменой `app._is_mac` и `widgets.is_aqua`.
- Фоновые операции Tk (`after`) не должны переживать окно; в тестах после `destroy` не оставлять отложенных вызовов (шум «invalid command name … after script» — признак утечки).
- Перед удалением «устаревшего» кода проверять `pyflakes`/`vulture` и поиск по репозиторию.

## Git, PR и релизы

- Работать в ветке от актуального `main` (`feat/…`, `fix/…`, `docs/…`); в `main` напрямую не коммитить. Коммиты — на русском, в конце: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Описание PR заканчивается строкой `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- **Не пушить в ветки уже влитых PR** — для новой правки открывать новую ветку и новый PR.
- **Сливать PR и выпускать релиз только по прямой просьбе пользователя.** Стандартная фраза-триггер: «слей все PR и выпусти релиз». Порядок:
  1. `gh pr list --state open`; зависимые (stacked) PR перенацелить на `main`; слить `gh pr merge <N> --merge`;
  2. `git checkout main && git pull`, поставить следующий тег версии (`1.0.N`) и `git push origin <тег>`;
  3. дождаться зелёной сборки «Сборка» (macOS и Windows), не опрашивая CI циклом сна — достаточно `gh run watch`;
  4. добавить русские описания релиза: `gh release edit <тег> --title … --notes …` (что изменилось для пользователя);
  5. пересобрать локальное приложение из `main`: `./build.sh`.
- После открытия PR смотреть статус проверок (`gh pr checks`); авто-слияние не включать без просьбы.
- Рабочие и временные файлы — в scratchpad сессии, не в репозитории.
